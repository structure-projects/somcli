# 场景：镜像生命周期管理

> 覆盖验收场景：SC-C05、SC-X10。

`somcli images` 管 Docker 镜像的拉、推、导出、导入。四个子命令都吃同一份镜像清单，
区别只是"从哪来 / 到哪去"。

```bash
somcli images pull     # 拉到本地
somcli images push     # 推到仓库
somcli images export   # 打包成离线归档
somcli images import   # 从离线归档载入
```

所有子命令都依赖本机的 `docker` 守护进程——somcli 只是拼 `docker pull/push/save/load`，
不自己实现镜像协议。

## 镜像清单从哪来

按优先级：

1. `-f/--file <path>`：显式给一个清单文件，三种写法都认（见下）。
2. `-s/--scope`：`harbor` 或 `k8s`，somcli 按顺序在当前目录、
   `~/.config/somcli/`、可执行文件同目录找 `harbor-images.yaml` / `k8s-images.yaml`；
   找不到就退化成内置的一两个镜像（`library/nginx:latest` / `k8s.gcr.io/pause:3.7`）。
3. `-s all`（默认）：harbor + k8s 两份合并。

`-f` 认的三种写法：

- **整份 somcli 配置**：取它的 `images:` 段（和 `install -f` 是同一份配置）。
- **裸 YAML 列表**：
  ```yaml
  - name: library/nginx
    tag: latest
  - name: goharbor/nginx-photon
    tag: v2.5.0
  ```
- **纯文本**：每行一个 `name:tag`，`#` 开头是注释。
  ```text
  nginx:latest
  goharbor/nginx-photon:v2.5.0
  ```

纯文本按**最后一个冒号**切 name/tag，所以 `registry:5000/nginx:latest` 不会把端口当 tag。

## 拉取 pull

```bash
somcli images pull -f configs/examples/image-list.txt
```

| 标志 | 默认 | 说明 |
|---|---|---|
| `-s, --scope` | `all` | `harbor` / `k8s` / `all`（`-f` 给了就忽略 scope） |
| `-r, --repo` | 空 | 拉取时拼在镜像名前的仓库前缀，如 `harbor.example.com/library` |
| `-f, --file` | 空 | 自定义镜像清单 |
| `-o, --output` | 空 | 把**成功拉取的清单**写成 YAML（给下游 push 当 `-i` 用） |

`-r` 非空时，somcli 从 `<repo>/<name>:<tag>` 拉，再 `docker tag` 回 `<name>:<tag>`，
本地留下的是不带仓库前缀的名字。

`-o` 只在**全部成功**时写——它是"这些镜像确实已在本地"的凭据，有一张失败就不写，
免得把没拉成的镜像喂给下一步。逐张失败不打断整批，但命令整体非 0 退出。

## 推送 push

```bash
somcli images push -i configs/examples/image-list.txt -r harbor.example.com/library
```

| 标志 | 默认 | 说明 |
|---|---|---|
| `-s, --scope` | `all` | 同上 |
| `-r, --repo` | 空 | 目标仓库前缀；非空时先 `docker tag` 成 `<repo>/<name>:<tag>` 再推 |
| `-i, --input` | 空 | 镜像清单文件（同 pull 的 `-f`） |

push 不做登录——推送前自己 `docker login` 好目标仓库。逐张失败不打断，整体非 0。

## 导出 export（离线包）

```bash
somcli images export -f configs/examples/image-list.txt -o images.tar.gz
```

| 标志 | 默认 | 说明 |
|---|---|---|
| `-s, --scope` | `all` | 同上 |
| `-r, --repo` | 空 | 要保存的镜像名前缀（源仓库） |
| `-f, --file` | 空 | 自定义镜像清单 |
| `-o, --output` | `images.tar.gz` | 导出归档路径 |

导出的是一个 gzip tar，里面每张镜像一个 `docker save` 出来的 `.tar`。
任何一张 save 失败、或归档写到一半出错，**整个输出文件会被删掉**——半截归档比没有更危险，
它看着像能用的离线包，要等到目标机 import 才暴露。中间产物落在
`<workdir>/tmp/export-*`，结束自动清。

## 导入 import（离线包）

```bash
somcli images import -i k8s-images.tar.gz
```

| 标志 | 默认 | 说明 |
|---|---|---|
| `-s, --scope` | `all` | 校验用（导入不按 scope 选镜像） |
| `-i, --input` | `images.tar.gz` | 归档路径 |

import 逐条 `docker load`。归档是外部输入，somcli 拒绝绝对路径和 `..` 越界的条目名，
只解压常规文件——软链、设备节点一律跳过，避免"导入镜像"变成往任意路径写内容。

## 典型离线流转

联网机上：

```bash
somcli images pull -f config.yaml -o pulled.yaml
somcli images export -f pulled.yaml -o images.tar.gz
```

把 `images.tar.gz` 拷到离线机：

```bash
somcli images import -i images.tar.gz
```

完整离线部署（含二进制/脚本资源）见 [`10-离线部署.md`](10-离线部署.md)。
命令与标志以 [`11-命令参考.md`](11-命令参考.md) 为准。
