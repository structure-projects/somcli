# 环境初始化

环境初始化解决两个问题：目标机器装系统包要能连上软件源（国内网络/离线网络），
以及下载的产物放在哪里、离线模式下怎么用。

## 1. 软件源（`source`）

顶层 `source:` 块配置"装系统包前先把源配好"。它是节点级前置动作：任何资源用
`method: package` 装包前，somcli 会先在**目标节点**上按这里的配置换源。探测与执行
都在目标上，操作机是什么发行版无关。

```yaml
source:
  mode: aliyun      # official（默认）/ aliyun / iso
```

| 模式 | 行为 |
|---|---|
| `official` | 不改源，用系统自带默认源（留空或不写 `source` 也是这个效果） |
| `aliyun` | 换成阿里云镜像，支持 apt / dnf / yum / zypper / apk；换源后刷新元数据（apt update / dnf makecache 等） |
| `iso` | 把目标节点上的 ISO 挂成本地源（yum/dnf 与 apt）；挂载点默认 `/mnt/somcli-iso` |

`mode: iso` 时 ISO 必须预先分发到目标节点——somcli 只负责挂载与写 repo 文件，
不传输 ISO（体积大，应由文件资源或离线介质分发）：

```yaml
source:
  mode: iso
  iso: /mnt/CentOS-7-x86_64.iso   # ISO 在目标节点上的绝对路径
  mount: /mnt/somcli-iso          # 挂载点，留空取默认
```

`source` 对所有 `method: package` 资源生效；非 package 资源不受影响。

## 2. 离线模式

- 标志 `--offline` 或顶层 `offline: true`：不发起任何下载，假设产物已经在缓存目录里。
  适合内网/无网络环境——先在有网机器上 `somcli download` 把产物下全，把整个工作目录
  搬到离线机器，再 `somcli install --offline`。
- `--github-proxy <url>` 或顶层 `github_proxy:`：给 GitHub 的下载地址加前缀代理
  （如 `https://gh-proxy.com/`），缓解国内拉取 GitHub release 超时。

离线整体流程（镜像导出/导入、仓库同步）见 [`10-离线部署.md`](10-离线部署.md)。

## 3. 工作目录与缓存布局

`--workdir`（或顶层 `workdir:`）指定工作目录，缺省是当前目录下的 `somwork/`
（当前目录已存在 `somwork` 时自动用它，否则用当前目录）。目录布局：

```
<workdir>/
├── download/        # 下载产物缓存，按 <name>/<version>/ 分目录
│   └── <name>/<version>/...
├── apps/            # 应用相关产物
├── data/            # 运行数据
├── scripts/         # 脚本
├── images/          # 镜像导出归档
├── logs/            # 日志
└── state.json       # 安装状态记录（幂等判据）
```

- 模板里用 `{{.WorkDir}}`、`{{.CacheDir}}`、`{{.DownloadDir}}` 等引用这些路径，
  完整变量表见 [`02-资源编排.md`](02-资源编排.md) §6。
- `state.json` 记录每个资源在每个目标上装过的版本，是幂等跳过的依据。
  `somcli status` 查看记录；改资源 `version:` 或加 `--force` 会重新执行。
