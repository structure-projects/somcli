# 平台兼容矩阵

> 覆盖验收场景：SC-P01、SC-P02、SC-P03、SC-P04、SC-P05、SC-P06、SC-P07、SC-P08、SC-P09、SC-P10、SC-C02。

somcli 跑在**操作机**上，通过 SSH 去装**目标节点**。两类机器的支持范围不同，
下面分开列。支持级别分三档：

- **完整**：代码支持，且 CI 在此格上真实跑过。
- **实验**：代码路径通，但上游依赖或 CI 覆盖不全，生产使用前自行验证。
- **不支持**：明确不可用或不产出产物。

## 操作机（跑 somcli 的机器）

| OS / 架构 | amd64 | arm64 |
|---|---|---|
| Linux | 完整 | 完整 |
| macOS | 完整 | 完整 |
| Windows | 不支持 | 不支持 |

`build.sh` 是构建矩阵的唯一来源，产出四个二进制：`somcli-{linux,darwin}-{amd64,arm64}`。
不产 Windows 产物——somcli 依赖 sh/ssh/scp/systemctl，Windows 不在支持范围。
CI 在 `ubuntu-latest`、`ubuntu-24.04-arm`、`macos-latest` 上跑同一套本地功能测试。

操作机只负责调度与文件中转，不在本机装集群；Linux 与 macOS 行为一致。

## 目标节点架构（被安装的机器）

目标节点必须是 Linux。

| 场景 | amd64 (x86_64) | arm64 (aarch64) |
|---|---|---|
| 工具编排 / 离线下载 / 镜像管理 | 完整 | 完整 |
| Docker 安装 | 完整 | 完整 |
| Docker Swarm 集群 | 完整 | 完整 |
| Kubernetes 集群 | 完整 | 实验 |

arm64 上 k8s 标实验，是因为 kubeadm 依赖的部分上游资产（个别 CNI 插件、
`cri-dockerd` 旧资产）在 arm64 上不齐；默认 containerd 运行时可装，但 CI 的
k8s 端到端用例只在 amd64 上跑。其余场景的下载 URL 已用 `{{.Arch}}`/`{{.UnameArch}}`
参数化，不再硬编码 amd64。

## 目标节点发行版

包管理器抽象在 `pkg/utils/packagemanager.go`，以下发行版由 integration CI 的
发行版矩阵逐格验证：

| 发行版 | 包管理器 | 备注 |
|---|---|---|
| CentOS 7 | yum | 已 EOL，CI 内置切到 vault.centos.org 源 |
| Rocky Linux 9 | dnf | RHEL 系推荐 |
| Ubuntu 22.04 | apt | |
| Debian 12 | apt | |
| openSUSE Leap 15.6 | zypper | |
| Alpine 3.20 | apk | 在容器里跑 somcli 需补 `libc6-compat` |

新发行版只要提供这五种包管理器之一（yum/dnf/apt/zypper/apk），`method: package`
就能工作；不在表内的不拦截，但不保证经过验证。

## 不支持与已知限制

- **Windows 节点**：不支持，节点必须 Linux。
- **k8s 1.24+ 配 docker 运行时**：dockershim 已移除，校验阶段直接拒绝，见
  [`06-场景-Kubernetes.md`](06-场景-Kubernetes.md)。
- **macOS 作为目标节点**：不支持（无法装 k8s/swarm 节点）；macOS 只能当操作机。
- 架构必须与离线包匹配：`x86_64` 下渲染的 `{{.Arch}}=amd64` 产物不能拿到 arm64 用。

命令与标志以 [`11-命令参考.md`](11-命令参考.md) 为准。
