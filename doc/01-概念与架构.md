# 概念与架构

> 覆盖验收场景：SC-E01、SC-E02、SC-E06、SC-E08、SC-E16、SC-X04、SC-X05、SC-X07、SC-X09、SC-X12、SC-X13。

somcli 是一个"环境初始化 + 工具/服务编排实施"引擎。它读一份声明式配置，
把资源按顺序下载、分发到目标机器、并在目标上执行安装。容器集群（k8s/swarm）
的安装只是这套引擎的一个应用场景。

## 核心概念

### 资源（Resource）

资源是编排的最小单位：一件要装的东西。它可以是一个裸二进制、一个系统包、一个容器镜像、
一份源码、或一段要 `kubectl apply` 的清单。资源声明自己的下载地址、安装方式（`method`）、
落到哪些机器（`hosts`）、以及安装前后的脚本。完整字段见
[`02-资源编排.md`](02-资源编排.md)。

### 节点（Node）

节点是操作的目标机器。`nodes:` 清单声明每台机器的 `host`、`ip`、`user`、`sshKey`、`role`。
资源用 `hosts:` 点名要落到哪些节点——按 `host` 或 `ip` 匹配。不写 `hosts` 的资源在
操作机本地执行。`hosts` 里的名字必须在 `nodes` 里声明，只有 `localhost`/`127.0.0.1`/`::1`
例外。

### 编排模型

一份配置可以同时描述 `resources`、`nodes`、`cluster`、`images` 四段，各命令只取自己那一段：

| 命令 | 消费的段 |
|---|---|
| `install` / `uninstall` / `download` | `resources`（以及它们引用的 `nodes`） |
| `cluster create` / `remove` / `add-node` / `remove-node` | `cluster` |
| `images pull` / `push` / `export` / `import` | `images` |
| `validate` | 全部（解析 + 渲染 + 引用完整性） |

这样同一套环境不必维护三份互相抄的配置。

## 执行模型

### 资源的生命周期

每个资源按固定顺序处理，分发与执行都在**目标节点**上：

1. **确定目标**：先做幂等判定（`check:` 探针、`state.json` 版本记录）。命中跳过的资源
   连下载都不做；加 `--force` 则无视判定强制执行。
2. **准备文件**：在操作机下载 `urls`，再通过 SSH 拷到每个目标的同一条绝对路径；
   渲染并落盘 `extra_files`。本机目标跳过分发。
3. **执行脚本**：依次跑 `pre_install` → `method` 实施 → `post_install`。
   `method` 只负责"把东西装上"，前置检查与收尾配置交给前后脚本。
4. **记录状态**：每个资源装完立即写 `state.json`，不等整轮结束——中途失败时
   前面装好的资源留下记录，重跑不会全部重装。

`uninstall` 按资源声明的**逆序**执行 `remove_scripts`，先装的后拆。

### 远程与本机的统一

method 实现不自己去 `exec`，而是把动作**编译成一串 shell 命令**，交给统一的
`RunScriptsDetailed` 执行。"在本机跑还是逐台 SSH 跑"只有一处实现，日志前缀、失败传播、
`--parallel` 并发、`on_error` 容错因此在所有 method 上行为一致。包管理器探测、换源
等动作都发生在**目标节点**上，操作机是什么发行版无关。

### 失败策略

- `on_error: abort`（默认）：第一个资源失败立即中止。
- `on_error: continue`：跳过失败的目标与资源继续后续，失败目标从后续阶段剔除，
  但进程退出码仍非 0——不会让半装环境假装成功。

## 代码结构

```
cmd/             命令行定义（cobra）；解析标志、调用下层
pkg/installer/   资源编排引擎：下载分发、method 分发、脚本执行、幂等、状态
pkg/cluster/     集群编排：k8s/swarm 的 create/remove/伸缩，内置安装清单
pkg/utils/       配置加载、模板渲染、SSH、包管理器、换源、下载器
pkg/types/       配置结构体（ResourceConfig / Resource / ClusterSpec ...）
pkg/state/       state.json 读写
configs/         示例配置与 k8s 安装清单（编译进二进制）
hack/            文档生成器
test/            黑盒测试（local / remote / multinode / cluster / swarm）
```

命令层不直接操作机器，所有"做事"的逻辑在 `pkg/` 里，命令层只负责把标志翻译成调用。
`test/` 不 import `pkg/`，一律编译出二进制再喂真实配置、跑真实命令来验证行为。
