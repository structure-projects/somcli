# 场景：离线部署

somcli 的离线能力建立在"下载与安装分离"上：联网机把资源和镜像都准备好，
整包拷到内网机，内网机用 `--offline` 安装，全程不联网。

离线模式有两种开法：全局标志 `--offline`，或环境变量 `SOMCLI_OFFLINE=true`。
开启后，下载器只认缓存——文件在就用，不在就直接报错说缺哪个，不会偷偷联网，
也不会静默当成功。

工作目录布局（`downloads/`、`apps/`、`tmp/` 等）见
[`03-环境初始化.md`](03-环境初始化.md)。整包迁移时把整个 workdir 拷走就行。

## 第一步：联网机准备资源

```bash
somcli download -f config.yaml
```

`download` 把配置里所有带 `urls:` 的资源下到 `<workdir>/downloads/`，
相对 `target:` 落在缓存目录下，绝对路径原样使用。它只下载、不安装，适合做"预热"。
`-q/--quiet` 静默。

## 第二步：联网机准备镜像

```bash
somcli images pull -f config.yaml -o pulled.yaml
somcli images export -f pulled.yaml -o images.tar.gz
```

`pull` 把 `images:` 段里的镜像拉到本地 docker；`export` 把它们 `docker save`
打成一个 gzip tar。详见 [`08-镜像管理.md`](08-镜像管理.md)。

> 注意：`export` 只保存本地已有的镜像，所以必须先 `pull`（或镜像本来就在本地）。
> 任何一张失败都不会产出半截归档。

Harbor 这类"自带安装包下载"的组件，其安装包也是经统一下载器获取的——
用 `somcli download` 把对应 URL 预先下到缓存路径，内网机 `registry install --offline`
就会直接命中缓存。

## 第三步：拷贝到内网机

把整个 workdir（含 `downloads/`、`apps/` 已解压内容）和 `images.tar.gz` 一起拷过去。
两台机的架构要一致（`x86_64` 的包不能拿到 `arm64` 上用）；URL 模板里的
`{{.Arch}}` / `{{.UnameArch}}` 在下载时已按当前机渲染，不会在内网机重新计算。

## 第四步：内网机离线安装

```bash
somcli install --offline -f config.yaml
somcli images import -i images.tar.gz
```

`install --offline` 跑资源的安装脚本时，所有下载动作都改成"查缓存"；
缺文件会明确报 `离线模式下文件不存在: <path>`，提示回联网机补下。
镜像用 `images import` 从归档 `docker load` 进本地。

## 校验

```bash
somcli validate -f config.yaml
docker images
```

`validate` 只校验配置结构与引用完整性，不连节点、不检查缓存是否齐全——
缓存是否齐要等 `install --offline` 真跑才知道。

完整命令与标志见 [`11-命令参考.md`](11-命令参考.md)。
