# 场景：业务服务编排

> 覆盖验收场景：SC-E09、SC-E11、SC-E12、SC-E15。

用 somcli 部署自己的业务服务：用 `vars` 参数化多套环境，用 `version` 驱动升级与回滚，
用 `extra_files` 落配置，用 `remove_scripts` 定义卸载。完整示例是
[`configs/examples/webservice.yaml`](../configs/examples/webservice.yaml)。

```bash
somcli validate -f configs/examples/webservice.yaml
somcli install  -f configs/examples/webservice.yaml
```

## 多环境参数化（`vars`）

`vars:` 定义模板变量，脚本与 `extra_files` 里用 `{{.Vars.xxx}}` 引用。
命令行 `--set k=v` 覆盖配置里的同名变量，因此同一份配置可以部署多套环境：

```bash
somcli install -f configs/examples/webservice.yaml --set env=staging --set replicas=3
somcli install -f configs/examples/webservice.yaml --set env=production --set replicas=10
```

示例里 `extra_files` 用变量渲染出一份环境配置：

```yaml
  # 节选自 configs/examples/webservice.yaml，只展示 vars 如何喂给 extra_files。
  vars:
    env: "production"
    replicas: "2"
  resources:
    - name: "webservice-config"
      version: "1.0.0"
      extra_files:
        "/etc/webservice/webservice.env": |
          ENV={{.Vars.env}}
          REPLICAS={{.Vars.replicas}}
          IMAGE={{.Vars.image_repo}}:{{.Version}}
```

`extra_files` 的键（目标路径）和值都过模板，在 `pre_install` 之前落盘到目标节点。

## 部署与升级

服务本身用 `method: container` 包装镜像，或用 `method: script` 写任意部署脚本。
升级就是把资源的 `version` 改大后重跑 `install`：

- `state.json` 记录每个资源装过的版本；版本相同则跳过，版本变化则重新执行。
- 想在不改版本时强制重装，加 `--force`。
- 单个资源升级：`somcli install -f <file> -n webservice`。

## 回滚

somcli 没有独立的 `rollback` 命令——回滚 = 把 `version` 改回上一个已知版本再 `install`。
状态按版本记录，旧版本会被重新应用。卸载用 `uninstall`，按资源声明逆序执行 `remove_scripts`。

## 幂等

- 给资源写 `check:` 探针：在目标上退出 0 就跳过整个资源，适合"装一次就够"的东西。
- 不写 `check` 时靠 `state.json` 的版本判幂等。
- 失败策略用 `on_error: continue` 让一个资源失败不阻断后续（退出码仍非 0）。

字段与模板变量全表见 [`02-资源编排.md`](02-资源编排.md)。
