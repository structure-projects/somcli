# Changelog

本文件记录 0.5.0-alpha 的变更。格式遵循 [Keep a Changelog](https://keepachangelog.com/zh-CN/1.1.0/)。

## [0.5.0-alpha] - 2026-08-22

对应提案 `20260818-migrate-phase3-platform-compat`（M3 平台兼容）。

这一版让 somcli 从"只在 amd64 + yum + 一种构建矩阵"走向跨发行版、跨架构：
`method: package` 现在按目标节点上实际存在的包管理器（apt/dnf/yum/zypper/apk）下发命令；
装包前可用顶层 `source:` 配置 official/aliyun/iso 三种软件源（国内换镜像、离线挂 ISO）；
下载 URL 全面参数化 `{{.Arch}}`/`{{.UnameArch}}`，arm64 引擎与工具编排完整可用，
k8s 集群安装在 arm64 上标注实验性；四处互相矛盾的构建矩阵收敛为 `build.sh` 单一来源。
同时补齐了 registry（harbor 安装校验、镜像同步）与 images（导出/导入全生命周期）的黑盒覆盖。

### BREAKING CHANGES

- **用可用的 `source:` 配置替换从未生效的 `--source` 标志与 `mirrors_source:` 段**。旧的
  "换源"能力是个空壳：`--source` 被声明为布尔标志却当作字符串切片读取（传参只会得到
  `["false"]`），而 `utils.InitSource` 里 `.sh` / `.iso` 两个分支都是空函数体——脚本不执行、
  ISO 不挂载，只打印一行"加载源"。本版把这套空壳整个删掉，并在同一位置给出真正可用的实现
  （见 Added"软件源配置"）。由于配置使用严格解析，仍保留旧 `mirrors_source:` 段的配置文件
  现在会直接报错而不是被忽略。

  迁移：删掉命令行上的 `--source`；把配置里的 `mirrors_source:` 段改成新的 `source:` 块：

  ```yaml
  source:
    mode: aliyun          # official（默认，用系统自带源）/ aliyun（阿里云镜像）/ iso（本地 ISO）
    iso: /mnt/os.iso      # 仅 mode: iso，ISO 在目标节点上的绝对路径
    mount: /mnt/somcli-iso
  ```

  注意：`somcli registry sync -s/--source`（源镜像仓库地址）是另一个独立且正常工作的标志，
  本次不涉及。

- **不再发布 Windows 二进制（`somcli-windows-amd64.exe`）**。本工具依赖 `sh`/`ssh`/`scp`/
  `systemctl` 与目标 Linux 节点交互，Windows 原生环境无法支撑这些能力，之前 Makefile 产出
  的 `.exe` 实际不可用。构建矩阵现统一为四个目标：linux/amd64、linux/arm64、darwin/amd64、
  darwin/arm64（`build.sh`、`Makefile build-all`、`go.yml`、`ci.yml` 四处一致）。

  迁移：Windows 用户请在 WSL2（Linux 发行版）或一台 Linux/macOS 操作机上运行 somcli。

### Added

- **发行版包管理器抽象（F10）**：`pkg/utils/packagemanager.go` 在生成的远端 shell 里用
  `command -v` 按优先级探测 apt-get/dnf/yum/zypper/apk（另含 brew），命中谁用谁；包名经
  单引号转义防注入；`sudo` 与环境变量按 `sudo env VAR=v cmd` 的正确顺序组合；非 root 执行
  失败时补提权提示。`method: package` 不再在业务代码里出现裸 `yum`/`apt`。
- **6 个发行版的容器矩阵**（`integration.yml` 的 distros job）：centos:7（yum）、
  rockylinux:9（dnf）、ubuntu:22.04 / debian:12（apt）、opensuse/leap:15.6（zypper）、
  alpine:3.20（apk），每个都真的用 `method: package` 装上 `make` 并验证可执行。
  CentOS 7 因官方源已 EOL，在流水线内切到 vault 存档源。
- **软件源配置（F12）**：顶层 `source:` 块在每个 `method: package` 装包前自动配好目标节点
  软件源。三种模式：`official`（默认，不改源，用系统自带）、`aliyun`（按探测到的包管理器
  apt/dnf/yum/zypper/apk 把官方源 sed 成阿里云镜像并刷新元数据，CentOS 7 指向
  `centos-vault/7.9.2009`）、`iso`（把目标节点上已存在的 ISO 挂载成 `file://` 本地源，
  yum/dnf 同时配 root/BaseOS/AppStream 三个 baseurl 用 `skip_if_unavailable` 兼容
  CentOS 7 与 RHEL/Rocky 8+，apt 从 `/etc/os-release` 取代号）。探测与执行都在目标节点上，
  ISO 需预先分发到目标，somcli 只挂载不配源。
- **arm64 支持**：`configs/**` 与 `configs/k8s/**` 的下载 URL 改用 `{{.Arch}}`（GOARCH：
  amd64/arm64，用于 k8s/containerd/runc/cni/cri-dockerd/crictl）与 `{{.UnameArch}}`
  （uname -m：x86_64/aarch64，用于 docker 静态包与 compose）；解除 `kubernetes.go` 对
  非 amd64 的硬拒绝，amd64 与 arm64 两档精确匹配放行。k8s 集群安装在 arm64 上为实验性
  （上游 cri-dockerd 与部分 CNI 资产不齐）。
- **registry 黑盒覆盖（SC-C03/C04）**：harbor install 的 hostname/版本/前置依赖校验；
  sync 的 `pull→tag→push→rmi` 编排、单张失败聚合不中断、cleanup 仅在推送成功后执行；
  顺手锁定 E6（`registry uninstall` 不再蹭 install 的 hostname 校验）。
- **images 导出/导入生命周期覆盖（SC-C05）**：`export` 产合法 gzip、单张 save 失败时删除
  半截归档；`import` 逐条 `docker load`、非 gzip 输入明确拒绝。
- **三种镜像清单写法（SC-X10）**：`images -f` 认统一配置的 `images:` 段、裸 `name/tag`
  列表、纯文本 `name:tag` 每行一种。
- **`test/fixtures/base-deps.yaml`**：跨发行版最小基础依赖清单（`make`，五个发行版包名一致）。

### Fixed

- **G9：`images pull/push` 的 `-o/-i` 默认值在子命令间泄漏**。四个 images 子命令曾共用同一个
  包级变量接 `-o`/`-i`，而 pflag 在注册时即写入默认值，于是 `export`/`import` 的默认
  `images.tar.gz` 泄漏给 `pull`/`push`：`images pull` 不带 `-o` 会在当前目录凭空写一个
  名为 `images.tar.gz` 的 YAML 清单，`images push` 不带 `-i` 不去用内置清单反而去读不存在的
  `images.tar.gz`。已拆为四个独立变量并加回归用例。
- **Makefile 的版本注入失效**：`-X main.Version=` 是空操作，因为版本变量在 `cmd` 包
  （`cmd.Version`）而非 `main`；Makefile 编出来的二进制永远是默认版本串。已改为正确的
  `-X github.com/structure-projects/somcli/cmd.Version=`。
- **`build.sh` 版本号写死**：改为从 `git describe --tags --always --dirty` 派生，与 Makefile 同源。
- **`install.sh` 的 arm64 识别**：Linux 之前硬编码 `somcli-linux-amd64`，arm64 机器装错二进制；
  现按 `uname -m` 映射 x86_64/amd64→amd64、aarch64/arm64→arm64。
- **`build.sh` / `install.sh` 的 shebang 位置**：`#!/bin/bash` 原本落在版权注释之后，
  移到文件首行才能被内核识别为脚本。
- **README 安装命令补 `aarch64→arm64` 映射**：原命令只处理 x86_64，arm64 Linux 下拼出的
  产物名不存在。

### Changed

- 构建矩阵收敛：`build.sh` 为 4 目标的唯一来源，`Makefile build-all` 与发布流水线 `go.yml`
  委托它，`ci.yml` 交叉编译矩阵同步为 4 目标。
- 移除从未生效的 `utils.InitSource` 与 `types.ResourceConfig.MirrorsSource` 字段，代之以
  `types.SourceConfig` 与 `utils.RenderSourceSetup`（official/aliyun/iso，见 Added）。
