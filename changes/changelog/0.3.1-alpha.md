# Changelog

本文件记录 0.3.1-alpha 的变更。格式遵循 [Keep a Changelog](https://keepachangelog.com/zh-CN/1.1.0/)。

## [0.3.1-alpha] - 2026-08-21

对应提案 `20260821-phase1-leftover-verification`（补齐 phase 1 的 5 条待验证场景）。

0.3.0-alpha 的「已知欠账」里，5 条场景保持 `pending` 的原因不是功能没做，
而是**验证环境当时没搭**；同时留了一个未决设计问题：somcli 该不该自己 `sudo`。
本版本把验证补齐、把那个问题落定，因此除 `--sudo` 之外没有行为变化。

无破坏性变更。

### Added

- **`install --sudo`**：给 `method: package` 生成的装包命令加 `sudo` 前缀，**默认不开**。
  不加时生成的命令与此前逐字相同，因此不是破坏性变更。
  前缀加在**生成的 shell 里**而不是 Go 侧 —— 提权必须发生在目标节点上，
  用操作机上跑 somcli 的身份去判断，一到远程就是错的。
  带环境变量的包管理器写成 `sudo env VAR=v cmd`：`sudo VAR=v cmd` 不是合法写法
  （sudo 会把 `VAR=v` 当成要执行的命令），`VAR=v sudo cmd` 又会被 sudo 的环境清洗丢掉。
  *不选自动判断的理由*：非 root 就自动加 sudo，等于用户没要求提权却被提权了。
  显式开关让"要不要提权"永远是用户说的。
  作用域只有 `method: package`；`method: binary` 的安装目录由 `install_dir` 决定，
  用户可以指向自己有权限的目录，不存在"必须提权"。
- **装包失败且执行者不是 root 时补一句提权提示**（"若是权限不足，请加 `--sudo` 或以 root 运行"），
  并原样传回包管理器的退出码。身份用 `id -u` 在生成的 shell 里判，同上。
  已经带 `--sudo` 时不提示 —— 那时失败多半不是权限问题。

### 验证补齐

以下都不改产品行为，只是让此前"声明了却没人验"的场景真的有载体。

- **SC-D10（远程已有同 hash 文件则不重传）** —— `test/multinode/dispatch_test.go`。
  判据取节点上文件的 **mtime 不变**，日志里的"跳过复制"只作辅证：
  日志说跳过、实际又传了一遍，只看日志的用例照样绿。
  本条原先规划在 remote 组，落地时挪到三节点组：remote 组的"远端"是回环别名 `127.0.0.2`，
  与操作机同一个文件系统 —— 源文件和目标文件是同一个文件，hash 永远相等，用例必绿且什么都没验。
- **SC-F03（`sshKey` 写 `~/.ssh/id_rsa` 时 `~` 能展开）** —— `test/remote/sshkey_test.go`。
  执行与分发两条路径都断言：M0 的 D13 修的就是"执行认 `~`、分发不认"这种一半对一半错。
  私钥不在 `HOME` 下时明确 skip，不让"绝对路径能用"冒充本条。
- **SC-C02 的另一半（当前架构的 compose 发布地址真实存在）** —— `test/local/compose_test.go`。
  此前的用例用假服务器，验的是"URL 里的架构名对不对"，验不了"这个 URL 真的存在"。
  新用例从 somcli **自己发出的请求**里还原出真实地址再发一次 HEAD，
  而不是在用例里把地址重算一遍 —— 重算的话验的是用例自己的算法。
  只在 CI 上跑（`ci.yml` 已有 amd64 与 arm64 两种机器，等于同时覆盖两个架构），本机跳过。
- **SC-M02 的另一半（在真实发行版上真把包装上）** —— `integration.yml` 新增 `distros` 作业，
  矩阵为 ubuntu 24.04 / debian 12 / fedora 41 / alpine 3.20 / openSUSE Leap 15.6，
  各自用 `method: package` 真装一次 `jq`，判据是装完 `jq --version` 能跑 ——
  只看 somcli 退出码 0 的话，包管理器静默失败照样绿。
  前置先确认镜像里没自带 `jq`，否则这条什么都没验。

### 已知欠账

- **SC-C01 的 multinode 半边（在真节点上装 docker）继续 `pending`**，且这一条短期内兑现不了：
  `somcli docker install` 调的是外部 `docker-manager.sh`，该脚本把安装写成必经步骤列表，
  其中 `start_service` 会 `systemctl daemon-reload / enable / start`，任一步非零就 `exit 1`。
  sshd 容器里没有 PID 1 的 systemd，`privileged: true` 也不会凭空长出一个 ——
  装到那一步必然失败，收窄后的断言（二进制到位、版本对、卸载后消失）压根到不了。
  要兑现得先把 docker 安装从 shell 脚本收进 Go。
  宁可留着 `pending`，也不要一个含义被悄悄改小的 `done`。
- 0.3.0-alpha 「已知欠账」中未在本版本处理的条目（节点可达性预检、`StrictHostKeyChecking=no`）依旧成立。
