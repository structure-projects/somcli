# Changelog

本文件记录 0.2.0-alpha 的变更。格式遵循 [Keep a Changelog](https://keepachangelog.com/zh-CN/1.1.0/)。

## [0.2.0-alpha] - 2026-08-19

对应提案 `20260818-migrate-phase0-trusted-signal`（架构收敛 M0：建立可信信号）。

本版本的主题是**让失败可见**。在此之前，安装失败也会打印 `✓ 成功` 并以退出码 0 结束，
声明为远程的编排会静默落到操作机上执行 —— 任何"验证通过"都不可信。
因此本版本有意引入三项破坏性变更：宁可让原先"看起来能跑"的配置和脚本立刻报错，
也不要继续让人以为装好了。

### ⚠️ BREAKING CHANGES

- **配置中的未知键从静默忽略改为报错。**
  三处加载路径（`utils.LoadConfig`、`cluster.LoadConfig`、`installer.LoadDownloadConfig`）
  统一改用 `yaml.UnmarshalStrict`。此前拼错的键会被默默丢弃，用户以为配了某个能力、
  实际从未生效。
  *影响*：任何含拼写错误、已废弃字段或尚未实现字段的配置文件将无法加载。
  *迁移*：升级后先跑 `somcli validate -f <你的配置>`，它会逐条列出问题且不做任何动作。

- **失败路径的退出码从 0 变为非 0。**
  `RunScripts` 不再吞掉脚本错误，下载失败会向上传播到 `install` / `download` 的退出码，
  `pre_install` 失败即中止且不再执行 `post_install`。
  *影响*：把 somcli 包在 shell 脚本或 CI 里的调用方，此前拿到的一直是 0，现在会看到真实结果。
  *迁移*：检查调用方是否依赖"somcli 永远成功"这一（错误的）假设。

- **配置中的 `cluster:` 由映射改为列表。**
  一份配置需要能同时描述多套集群（如 my-swarm 与 my-k8s），因此 `cluster:` 现在是
  `[]ClusterSpec`。
  *影响*：所有现存集群配置文件都需改写。
  *迁移*：把原先 `cluster:` 下的整块内容缩进为列表的第一项，并补上 `name:`：

  ```yaml
  # 旧
  cluster:
    type: k8s
    nodes: [...]

  # 新
  cluster:
    - type: k8s
      name: my-k8s      # 多套集群时用 --cluster-name 选中
      nodes: [...]
  ```

  多套集群共存时，`cluster create` / `cluster remove` 用 `--cluster-name` 或
  `--cluster-type` 指定操作哪一套；定不下来时命令会报错并列出候选，不再默默取第一套。

### Added

- `somcli validate -f <file>`：只读校验配置。走与 install 完全相同的加载与渲染路径，
  但不下载、不执行脚本、不写任何文件。严格解析上线后，用户需要一个"动手前先自查"的手段。
- 统一配置 schema：一份文件里 `resources` / `nodes` / `cluster` / `images` 与全局设置
  （`offline` / `debug` / `workdir` / `github_proxy` / `mirrors_source`）共存，
  各命令只取自己那一段，别人的段落原样放着不影响解析。
  `configs/config.yaml` 现在就是这样一份四段齐全的样例。
- `install -n/--name <resource>`：只安装配置里被点名的那一个资源。
- `cluster create --cluster-name`、`cluster remove --cluster-name` / `--cluster-type`：
  在多套集群的配置里选定操作对象。
- `images --custom-file` 接受三种输入：统一配置的 `images:` 段、裸列表、纯文本 `name:tag` 行。

### Fixed

- `RunScripts` 不再吞掉全部错误。此前它只打一行调试日志然后 `return nil`，
  失败的安装照样打印成功。
- `SetNode` 此前全仓库零调用点，导致 `GetNode` 查不到任何主机；`GetNode` 又会静默兜底成
  `127.0.0.1`。两者叠加的效果是：声明为远程的编排（含 `swapoff`、包管理器安装、
  `systemctl enable` 这类动作）会落到运行 somcli 的操作机上执行。
  现在集群配置加载时会登记节点表，`GetNode` 查不到就返回错误并列出已声明的节点，
  只有显式写 `localhost` / `127.0.0.1` / `::1` 才被当作本机目标。
- 脚本模板改用 `text/template`。此前用的是 `html/template`，它会把 shell 里的
  `&`、`'`、`<`、`>` 转义成 HTML 实体，渲染出来的命令与写下的不是同一条。
- 下载失败不再打印 `[SUCCESS]`，且会影响退出码。
- `somcli docker-compose --help` 不再触发真实的下载与安装。透传模式需要
  `DisableFlagParsing`，代价是 `--help` 也变成透传参数，现在在触碰安装器之前显式拦截；
  拦截时会先跳过 somcli 自己的全局 flag，所以
  `somcli --workdir /tmp/x docker-compose --help` 也不再有副作用。
- `--source` 的类型由 `bool` 改为字符串列表。帮助里一直写着 "comma-separated or multiple
  flags"，类型却是 bool：绑到 `mirrors_source` 后读回 `["false"]`，每条命令都白跑一次
  源初始化并打印 `加载源 -> [false]`，同时把配置文件里真正的 `mirrors_source` 盖掉。
- `sshKey` 里的 `~` 现在在所有分发入口都会展开。此前只有 `RunCommandOnNode` 展开，
  而 `scp` / `ssh` / `rsync` 那几个入口拿的是原样字符串，且它们是被 exec 直接拉起的、
  没有 shell 帮忙展开 —— 于是照示例配置（一律写 `~/.ssh/id_rsa`）写的人，文件分发一律失败。
- 按名安装（`InstallTool`）此前已实现但没有命令行入口，整条路径不可达。
- 纯文本镜像列表不再把带端口的镜像名切错：`registry:5000/nginx:latest` 现在按最后一个
  冒号切分，最后一段含 `/` 则判定为无 tag 并跳过，而不是产出 `name=registry` 去 pull。
- `install --help` 与文档中的命令、标志改为与实际注册的一致：
  `docker-images` → `images`、`offline download` → `download`、
  `cluster deploy` → `cluster create`、`registry install -h` → `-H`；
  删除未注册的 `docker uninstall --force`、`apply -f`、`images --username|--password`
  与 compose 的 `-v|-p`。`install --help` 不再声称支持 package/binary/source/container
  四种安装方式（实际只有 download → scripts 一条路径），并明说资源级 `method` 字段当前未被消费。
- `configs/kubernetes-cluster.yaml` 此前写了 5 个 YAML 文档而加载器只读第一个，
  后 4 段被静默丢弃；现在合成单文档，且 `validate` 会拒绝多文档文件并说明
  `---` 之后的内容不会生效。

### Changed

- CI 由恒绿改为真检查。旧的 `test.yml` 用 `go fmt ./...`（就地改写文件且始终退出 0），
  换成 `ci.yml`：`gofmt -l`（只列不改）、`go vet`、`yamllint`、三操作机矩阵
  （ubuntu / ubuntu-arm / macos）跑功能验证、五平台交叉编译并冒烟执行。
- 新增 `integration.yml` 承载需要真实 SSH 的验证：单远程节点（CI runner 自连接）
  与三节点 sshd 容器编排。两组在 CI 内硬失败而非跳过，不让"跳过"冒充"通过"。
- 功能验证一律黑盒：编译二进制 → 喂真实配置 → 跑真实命令 → 断言退出码 / 输出 /
  落盘产物 / 节点状态。`test/` 下禁止 import 本仓库的包，由 CI 守卫兜底。
  不设行覆盖率门槛 —— 覆盖率是白盒指标，进度以 `test/matrix.yaml` 的场景数衡量。

### Removed

- 删除白盒测试产物：`test/unit/`（直接调用 `pkg/` 导出函数、断言内部实现）、
  `test/coverage_matrix_test.go`（校验测试函数名是否含场景 ID，测的是测试自己）、
  `test/contract/config_test.go`（绕过二进制直接解析，且维护了一份"欠账清单必须准确"的自校验）。
- 删除 CI 的 `MIN_COVERAGE` 门槛与 `-coverpkg`。

### 已知欠账

- 下载器 shell out 到 `wget`，既无 `curl` 回退也未用 `net/http`。
  不带 wget 的机器（含 macOS 默认环境）无法下载，相关场景在这类机器上跳过。留待下一里程碑。
- 资源级 `method`、`res_type`、`files`、`extra_files`、`roles` 与 `configs/tools.yaml`
  里的 `package:` 仍未被消费，`install --help` 已明说这一点。
- 透传命令（`docker-compose`）的 somcli 全局 flag 仍不生效：
  `somcli --workdir X docker-compose up` 的产物落回 `./somwork`，且 `--workdir X` 会被
  当作 compose 参数透传。本版本只修了其中"帮助不再有副作用"这一半。
- `StrictHostKeyChecking=no`：首次连接不校验主机指纹，存在中间人风险。
