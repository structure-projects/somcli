# Changelog

本文件记录 0.4.0-alpha 的变更。格式遵循 [Keep a Changelog](https://keepachangelog.com/zh-CN/1.1.0/)。

## [0.4.0-alpha] - 2026-08-21

对应提案 `20260818-migrate-phase2-cluster-as-config`（把"集群装什么"从 Go 代码搬到配置，
并让 k8s 第一次真的能装上）。

这一版的核心是：`somcli cluster create` 此前即使装不上也会报"创建成功" ——
没装 CNI（节点永久 NotReady）、join 命令只取了半行（worker 必失败）、
多 master 的 `joinMaster` 是空壳、containerd 与 kubelet 的 cgroup 驱动打架。
本版把这些都修了，并把安装内容外置到 `configs/k8s/*.yaml`，换版本、加组件不再需要改代码。

### BREAKING CHANGES

以下变更会让此前能跑（或看似能跑）的配置改为在**连节点之前**直接报错。
这些"此前能跑"的配置没有一个是真能装成的，提前失败是为了不在节点上留下半截改动。

- **`k8sConfig.resources` 从被静默忽略变为生效**。留空时按 `containerRuntime` 装默认一套
  （containerd 路线：base-dependencies / cni-plugins / runc / containerd / kubernetes；
  docker 路线：base-dependencies / docker / kubernetes）；写了就按写的名字与顺序装，
  名字不在 `configs/k8s/` 清单里时报错并列出可用名单。

  迁移：此前写了 `resources` 但发现"不生效"的配置，现在它真的会按那份清单装。
  想要旧的默认行为就把这个键删掉。

- **`k8sConfig.runtime` 修正为 `containerRuntime`**。原键名是个无效拼写，解析时会被
  严格模式当成未知字段直接报错。取值不变：`containerd`（默认）或 `docker`。

- **多 master 但没有 `controlPlaneEndpoint` 改为拒绝**。此前会"成功"装出一个单点集群：
  其余 master 没有稳定的 apiserver 入口，证书 SAN 与 kubeconfig 无处可指，无从加入。

  迁移：在 `k8sConfig` 下补 `controlPlaneEndpoint: "<VIP 或 LB 地址>:6443"`，
  或只保留一个 master。

- **`k8sConfig.version` 必须是完整的三段发布版本号（形如 `1.30.4`）**。
  留空、写 `1.30` 这样的版本线、或带 `v` 前缀（`v1.30.4`）现在都直接拒绝：
  二进制下载地址是 `https://dl.k8s.io/v<版本>/bin/...`，那些写法拼出的 URL 必然 404，
  而旧版要到下载或 `kubeadm init` 才失败，且报错指不到根因。
  各组件版本键（`containerdVersion` / `runcVersion` / `cniPluginsVersion` /
  `dockerVersion` / `cniVersion`）同样不要带 `v` 前缀。

- **`containerRuntime: docker` 且 k8s ≥ 1.24 改为拒绝**。dockershim 在 1.24 已从 kubelet
  移除，本工具走的 `--cri-socket unix:///var/run/dockershim.sock` 在 1.24 及以上接不上。

  迁移：改用 `containerRuntime: containerd`，或把 `version` 降到 1.23.x。
  若必须用 docker，需要节点上先装 cri-dockerd 提供 CRI 端点（本版尚不支持，后续版本补）。

### Added

- **`somcli cluster add-node` / `somcli cluster remove-node`**：往已有集群加减一台节点，
  k8s 与 swarm 都支持。节点要先写进配置文件，命令只用 `--node <主机名>` 指名
  （凭据、角色、运行时都在配置里，不另开 `--ip/--user` 那套平行入口）。
  扩容只动新来的那一台，不在健康节点上重跑 swapoff/sysctl；缩容按 drain → 节点上重置 →
  从集群删记录的顺序，摘第一台 master/manager 会被拒绝（那是拆整个集群，该用 `cluster remove`）。
- **CNI 真正部署**：`cni: flannel`（默认）或 `cni: calico`，作为清单资源在
  `kubeadm init` 之后、worker 加入之前 `kubectl apply`。此前代码里完全没有这一步，
  装完节点永久 NotReady。
- **多 master 真正加入**：`kubeadm init` 带 `--upload-certs`，后续 master 用现场重新
  上传的证书 key 以 `--control-plane` 加入；fixture 用一台 haproxy 充当稳定入口验证。
- **`cluster remove` 把节点清干净**：按 worker 先、第一台 master 最后的顺序 `kubeadm reset`
  （带 `--cri-socket`），删 `/etc/kubernetes`、`/etc/cni/net.d`、CNI 网桥。
  判据是"同一批节点能再装一遍"，不是"某个目录没了"。
- **Swarm 全生命周期支持**：2 manager + 1 worker 的安装/扩缩容/移除，判据不止
  `docker node ls` 的字面，还要真的调度起服务。
- **安装内容全部外置到 `configs/k8s/*.yaml`** 并编译进二进制（可用 `SOMCLI_K8S_CATALOG`
  覆盖目录）：base-dependencies / cni-plugins / runc / containerd / docker / kubernetes /
  flannel / calico。`pkg/cluster` 里不再有资源字面量（CI 静态守卫）。
- **版本形状校验**（见 BREAKING）与安装时的版本回显：装上的组件版本与配置不一致时，
  日志里能直接看到装的到底是哪一版。

### Changed

- **`kubeadm join` 改为现场用 `kubeadm token create --print-join-command` 生成**，
  不再从 `kubeadm init` 输出里按行刮（旧实现取到的是半条命令，缺
  `--discovery-token-ca-cert-hash`，worker 必失败）；也不再把 join 命令落盘
  （token 24 小时过期，扩容时读到的是过期命令）。
- **containerd 配置写入 `SystemdCgroup = true`**，与 kubeadm 默认的 systemd cgroup 驱动
  对齐（此前两边打架，kubelet 反复重启）。
- **节点准备写入 `/etc/sysctl.d/k8s.conf`**（`bridge-nf-call-iptables`、`ip_forward`）
  与 `/etc/modules-load.d/k8s.conf`，不再依赖宿主碰巧已经配好。
- **新建第五个测试组 `swarm`**（`test/swarm/`，build tag / 目录名 / matrix env 同名）：
  swarm 场景不挂在 multinode 组，因为那组容器 PID 1 是 sshd 不是 systemd，装不上 docker；
  也不与 k8s 组共用容器（装 docker 会覆盖 containerd 配置，串台）。载体是每晚 e2e 的
  swarm job。

### Removed

- 一批全仓库零引用的死代码：`generateKubeadmConfig`、`SSHExec`/`SSHExecWithOutput`/
  `SSHClient` 及其仅有的被依赖方、`RsyncCopy` 及其版本比较帮手、`GetDownloadURL` 及其
  `SystemInfo` 一族、`NormalizeVersion`，以及一个遗留的备份文件
  `pkg/cluster/kubernetes.go_bak`。清理后不再有代码引用 `golang.org/x/crypto/ssh`。

### 已知欠账

- **D6 后半（cri-dockerd）**：`containerRuntime: docker` 在 k8s ≥ 1.24 仍是硬拒绝，
  等接上 cri-dockerd 后放宽为"缺 cri-dockerd 才拒绝"。
- **真集群 E2E 尚未转绿**：`test/cluster/` 与 `test/swarm/` 随每晚 `e2e.yml` 跑，
  matrix 里这些场景在流水线转绿并稳定前保持 `pending`，不提前勾 `done`。
- 版本矩阵本轮覆盖 1.28 / 1.29 / 1.30 三条线（各装一遍并核对 kubeadm/kubelet/apiserver
  三处版本），更老或更新的版本未在本版验证。
