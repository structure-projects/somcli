# 日志规范

> 通用规则，适用范围：所有技术栈和项目类型。

## 日志级别

| 级别 | 语义 | 使用场景 | 触发动作 |
|:----:|------|---------|---------|
| **ERROR** | 需要立即人工介入 | 数据库连接失败、支付回调验签失败、消息队列写入失败 | 告警 + 值班 |
| **WARN** | 异常但可自动恢复 | 重试成功、降级触发、业务异常（余额不足、库存不够） | 日报统计 |
| **INFO** | 关键业务流程节点 | 请求开始/结束、订单状态变更、用户登录/登出、定时任务执行 | 按需查询 |
| **DEBUG** | 开发调试信息 | 方法入参出参、SQL 参数、中间变量 | 仅开发/测试环境开启 |
| **TRACE** | 极致细节追踪 | 循环内变量、复杂算法每一步 | 一般不使用 |

- **MUST** 生产环境默认日志级别为 `INFO`。
- **SHOULD** 生产环境支持动态调整日志级别（无需重启），用于问题排查。

## 日志格式

### 结构化日志

- **MUST** 生产环境使用结构化日志格式（JSON），便于日志平台（ELK/Splunk/Loki）解析和检索。
- **SHOULD** 开发环境可使用可读的文本格式。

### 必须字段

每条关键业务日志 MUST 包含以下字段：

| 字段 | 说明 | 示例 |
|------|------|------|
| `timestamp` | ISO 8601 时间戳 | `2026-01-15T10:30:00.123Z` |
| `level` | 日志级别 | `INFO` |
| `service` | 服务名称 | `structure-order` |
| `traceId` | 请求追踪 ID | `abc123-def456` |
| `userId` | 操作人 ID | `10001` |
| `message` | 日志描述 | `订单创建成功` |
| `context` | 业务上下文 | `{"orderId": "ORD-001", "amount": 99.00}` |

### 示例

```json
{
  "timestamp": "2026-01-15T10:30:00.123Z",
  "level": "INFO",
  "service": "structure-order",
  "traceId": "abc123-def456",
  "userId": "10001",
  "message": "订单创建成功",
  "context": {
    "orderId": "ORD-2026-001",
    "amount": 99.00,
    "productId": "PROD-42",
    "channel": "APP"
  }
}
```

## 日志内容

### 必须记录

- **MUST** 所有关键业务流程节点：请求开始/结束、数据库操作（写）、外部调用、定时任务。
- **MUST** 所有 ERROR 级别日志包含足够上下文定位问题（traceId + 关键参数）。
- **MUST** 安全审计日志：登录/登出、权限变更、敏感数据访问、配置修改。
- **SHOULD** 关键业务节点记录执行耗时（通过 AOP 或中间件自动埋点）。

### 禁止记录

- **禁止** 记录密码、Token、密钥等敏感凭据。
- **禁止** 记录完整的身份证号、银行卡号、手机号（应脱敏后记录）。
- **禁止** 记录大量无意义的调试信息（如每毫秒打印一次心跳）。
- **禁止** 在循环内打印 `INFO` 级别日志。
- **禁止** 用日志代替异常处理 —— 先抛异常，再在异常处理器中记录。

### 脱敏规则

| 原始数据 | 脱敏后 |
|---------|--------|
| 手机号 `13812345678` | `138****5678` |
| 身份证 `320102199001011234` | `320***********1234` |
| 银行卡 `6222021234567890` | `6222********7890` |
| 邮箱 `user@example.com` | `u***@example.com` |
| Token `eyJhbGciOi...` | `eyJh***（截断至前6字符）` |

## 日志输出

- **MUST** 日志输出目标按环境区分：
  - **开发**：控制台（Console）
  - **测试**：控制台 + 文件
  - **生产**：文件（按日滚动，保留 30 天）+ 集中收集（ELK/Loki/阿里云 SLS）
- **MUST** 日志文件按大小或时间滚动，禁止单文件无限增长。
- **SHOULD** 异步日志输出，避免阻塞业务线程。

## 日志监控

- **MUST** ERROR 日志配置实时告警（如钉钉/企微/飞书/PagerDuty）。
- **SHOULD** WARN 日志按周期统计（日报/周报），关注趋势异常。
- **SHOULD** 配置日志量异常告警（如每分钟 ERROR 超过阈值）。

## 禁止事项

- **禁止** 在循环中打印 INFO 及以上级别日志。
- **禁止** 记录敏感信息（密码、Token、完整手机号/身份证/银行卡）。
- **禁止** 用 `System.out.println` / `console.log` / `print()` 代替日志框架。
- **禁止** 日志文件无限增长（无滚动策略）。
- **禁止** ERROR 日志无上下文（只有 `"出错了"` 无 traceId 无参数）。
