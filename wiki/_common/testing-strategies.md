# 测试策略

> 通用规则，适用范围：所有技术栈和项目类型。
> 各技术栈在其 `tester.md` 中定义框架特定的测试工具和配置。

## 测试工作流（MUST —— 与开发同步进行）

测试不是开发完成后的补充，而是开发过程的一部分。

### 功能开发节奏

```
开发功能 A → 编写功能 A 单元测试 → 单测通过 → 才能开始功能 B
```

- **MUST** 每开发一个功能，**立即**编写对应单元测试。
- **MUST** 单元测试**通过后**才能开始下一个功能。
- **禁止**"先把所有功能写完再补测试"。

### 功能修改节奏

```
修改功能 A → 同步修改功能 A 的测试代码 → 测试通过 → 修改完成
```

- **MUST** 功能代码有修改时，**同步修改对应测试代码**。
- **MUST** 修改后的测试**通过后**才算修改完成。
- **禁止** 只改功能代码不改测试、留下失败或过时的测试。

### 业务流程测试

```
业务模块编写完成 → 编写业务流程集成测试 → 通过 → 业务才算交付
```

- **MUST** 业务模块完成后，编写**业务流程级集成测试**，覆盖完整链路。
- **MUST** 业务流程测试通过后，该业务才算交付。

## 测试金字塔

```
        /\
       /E2E\         少量端到端测试：核心用户流程
      /------\
     / 集成测试 \      中量集成测试：数据库、API、消息队列
    /------------\
   /   单元测试    \    大量单元测试：业务逻辑、工具函数、算法
  /----------------\
```

| 层级 | 覆盖范围 | 启动依赖 | 占比建议 |
|------|---------|:--:|:--:|
| **单元测试** | 业务逻辑、算法、工具函数 | 无外部依赖（Mock 进程边界） | ~60% |
| **集成测试** | 数据库读写、API 契约、消息收发 | 真实中间件（Testcontainers / 嵌入式实例） | ~30% |
| **E2E 测试** | 核心用户流程 | 完整环境 | ~10% |

## 测试覆盖要求

### 必须覆盖

- **MUST** 正常路径（Happy Path）
- **MUST** 异常路径（Error Path）：参数不合法、资源不存在、权限不足
- **MUST** 边界条件：空值、零值、极大值、极小值、并发冲突
- **MUST** 分页场景：首页、末页、空页、单条、溢出页

### 断言有效性

- **MUST** 断言必须验证**行为与数据**，不只是返回码。
  - ✅ `assertEquals(expectedUser.getName(), result.getData().getName())`
  - ❌ `assertNotNull(response)`  // 僵尸断言，只验证非空无意义
- **MUST** 每个测试方法至少包含一个有意义的断言。
- **禁止** 为了覆盖率写僵尸断言。

## Mock 策略

- **MUST** Mock 只发生在**进程边界**：第三方 HTTP API、外部 SaaS、不可控硬件。
- **禁止** Mock 以下内容：
  - 数据库 / Redis / MQ / 搜索引擎（使用 Testcontainers 或嵌入式实例替代）
  - 同项目内的 Service / Repository（那是单元测试不是集成测试）
  - 时间（使用 Clock 抽象，可注入 `Clock.fixed()` 测试）
- **SHOULD** 外部 HTTP 依赖使用 WireMock / MockServer 替身。

## CI 门禁

| 时机 | 必须通过 |
|------|---------|
| **提交代码前** | 本地全量测试通过 |
| **提交代码前** | 本地编译通过 |
| **PR 合入前** | CI 测试流水线全部通过 |
| **发布前** | CI 全量测试通过 + 无 `@Disabled` 无关联 issue 的测试 |

- **禁止** 在测试失败或编译失败的情况下提交/合入/发布代码。
- **禁止** 为了"让测试通过"而删除/注释断言 —— 应修代码或修测试（并说明理由）。

## 测试命名

- **MUST** 测试文件名与被测文件对应：`UserService.java` → `UserServiceTest.java`。
- **SHOULD** 测试方法名描述场景：`shouldFailWhenUserNotFound()`、`shouldReturnPageWhenPageExceedsTotal()`。
- **SHOULD** 测试方法遵循 Given-When-Then 结构。

## 禁止事项

- **禁止** 提交无关联 issue 说明的 `@Disabled` / `@Skip` 测试。
- **禁止** 在测试中使用 `Thread.sleep()` 等待异步结果 —— 使用 Awaitility 或 CountDownLatch。
- **禁止** 集成测试 Mock 数据库/Redis/MQ —— 使用 Testcontainers。
- **禁止** 僵尸断言（`assertNotNull` 就完事）。
- **禁止** 测试依赖执行顺序（每个测试独立可运行）。
- **禁止** 测试依赖外部网络（第三方 API 必须 Mock）。
- **禁止** 测试失败/编译失败仍提交代码。
