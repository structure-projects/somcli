# Code Review 通用原则

> 通用规则，适用范围：所有技术栈和项目类型。

## 审查优先级

1. **安全** — 注入风险、敏感信息泄露、权限绕过
2. **正确性** — 边界条件、空值处理、异常处理
3. **性能** — N+1 查询、大循环、内存泄漏
4. **可维护性** — 命名清晰、函数短小、关注点分离
5. **一致性** — 遵循项目现有风格与约定

## 审查要点

- **MUST** 新增功能必须有对应的测试。
- **MUST** 不能引入已知的安全漏洞（CVE）。
- **SHOULD** 函数/方法不超过 50 行。
- **SHOULD** 避免硬编码（魔法数字、写死的 URL/路径）。
- **SHOULD** 代码注释解释"为什么"，而非"做什么"。

## 审查礼仪

- **MUST** 评论区分"必须改"（blocking）和"建议改"（non-blocking）。
- **SHOULD** 每条评论给出具体改进建议，而非只说"不好"。
